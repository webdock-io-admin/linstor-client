# drbd-options: take values without unit in the option's default unit

Refs: LINBIT/linstor-client#59

## Problem

`linstor rd drbd-options --c-max-rate 4194304 <rd>` stores
`DrbdOptions/PeerDevice/c-max-rate=4096` instead of `4194304`, while
`linstor rd set-property <rd> DrbdOptions/PeerDevice/c-max-rate 4194304`
stores the value as given. The same applies to every byte-unit option whose
default unit is not bytes: KiB/s options (`c-max-rate`, `resync-rate`, ...) and
sector options (`c-fill-target`, `congestion-fill`, `peer-ack-window`).

## Cause

`linstor_client/commands/drbd_setup_cmds.py:157` (upstream master 487cb9b) passes
the value to `SizeCalc.auto_convert(value, unit)`. `SizeCalc.parse_unit`
(python-linstor 1.29.1, `linstor/size_calc.py:71-74`) assumes bytes when the
value has no unit suffix, so a bare `4194304` is read as 4194304 bytes and
converted to 4096 KiB/s.

This contradicts the documented behaviour in be36d9a ("DRBD-Options: Fix help
text"): "If the user enters a value without a unit, "k" is taken as a unit ...
`--resync-rate 100` results in 100KiB/s", and the help text "Default unit: k".

## Fix

`linstor_client/commands/drbd_setup_cmds.py:157-162`: if the value is a plain
non-negative integer, it is taken as already being in the option's default unit
(as set-property does) and only range-checked. Values with a unit suffix are
converted with `SizeCalc.auto_convert` as before. Options whose default unit is
bytes behave the same as before.

## Dev-rack result

Webdock dev rack (node u25), LINSTOR controller 1.35.2, throwaway resource
group. Each property was cleared before each set and read back with
`linstor rg lp`.

| Command (`rg drbd-options ...`) | Stored by client 1.29.1 | Stored with this branch (638e6f2) |
|---|---|---|
| `--c-max-rate 4194304` | 4096 | 4194304 |
| `--c-max-rate 4M` | 4096 | 4096 |
| `--c-fill-target 2048` | 4 | 2048 |

All six results as expected: bare values are now stored in the option's
default unit (KiB/s, sectors), and values with a unit suffix are converted as
before.
